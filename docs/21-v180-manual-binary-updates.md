# 1.8.0：手动检查与二进制差分更新

## 用户操作

设置 → 关于 → 检查更新。启动软件、打开关于、日常编辑均不会主动检查或提示新版本。检查和下载是可选的联网操作，普通编辑及 PDF 导出继续离线。

发现新版后查看说明，再点击下载更新。下载和准备过程中可取消，期间可以继续编辑。准备完毕选择“重启并更新”：软件先检查未保存输入、保存失败以及 AI、生成和导出任务，满足条件后退出，再由独立更新窗口替换文件。独立窗口也提供取消，取消后先恢复原程序再打开软件。

**1.7.3 及更早版本没有更新入口，需要先手动解压覆盖到 1.8.0；之后才能使用软件内更新。**

## 更新源可配置

首次手动检查时在软件根目录创建 `update-source.json`，仅在文件不存在时采用默认配置。它是个人配置，不进入程序更新清单或分发 ZIP，覆盖更新和软件内更新都不会覆盖它。

默认配置来自 `assets/update-source.default.json`，不是写死在业务代码中的地址：

```json
{
  "provider": "github",
  "apiBase": "https://api.github.com",
  "repository": "Ewanice/Memorybook",
  "manifestAsset": "update-manifest.json"
}
```

也支持静态托管：

```json
{
  "provider": "static",
  "manifestUrl": "https://example.com/updates/update-manifest.json"
}
```

静态更新附件与清单置于同一目录。正式网络地址必须 HTTPS，只有本机回环地址允许 HTTP，供自动化测试使用。修改更新源不会改变签名信任：仍然只接受软件内置公钥验证通过的清单。用户不需 GitHub 登录或 Token。下载使用独立网络会话，采用系统网络代理；不会解除编辑窗口的禁止远程资源规则。

## 发布附件和差分格式

除完整 ZIP 与 SHA256SUMS 外，每次发布包含：

- `update-manifest.json`：Ed25519 签名信封，载明版本、说明、资料兼容版本、程序文件摘要、压缩段位置及可用补丁。
- `Memorybook-update-full.bin`：各程序文件独立 gzip 压缩后顺序拼接的完整恢复内容。
- `Memorybook-update-delta.bin`：相对上一次发布内容生成的二进制补丁，以及新增或不适合差分的小文件。

MBDELTA1 使用固定 64 KiB 内容块索引，将新版文件表示为旧文件 COPY 和新增 DATA 指令，再 gzip 压缩。允许复用移动过的完整块；位移较大、没有合适复用块时自动使用完整文件。补丁含旧文件及目标文件的大小与 SHA-256；读取、COPY 范围、输出长度及压缩展开均有上限。不会将补丁当脚本或代码执行。

客户端先比较本机文件摘要，只准备变化的程序文件。原文件摘要匹配时采用差分；不匹配或缺少文件时使用完整来源。完整来源和差分来源都有签名摘要；网络损坏和签名错误直接停止，不能借“回退”绕过校验。

更新附件直接由 GitHub Release 托管，无需自建后端。Git LFS 用于仓库中的完整 ZIP 和素材，不承担客户端更新协议。

## 程序替换和恢复

`Memorybook.exe` 是一个小型 Windows 启动与恢复程序，实际 Electron 程序为 `Memorybook.App.exe`，使用时仍只需双击前者。启动器使用 Windows 10/11 通常已包含的 .NET Framework 4 系列运行库。Electron 的 ASAR 完整性校验继续启用。

下载、解压和补丁重建全部发生在当前软件的 `.updates/` 内，重建文件通过校验后才进入可安装状态。安装时将独立更新器复制到事务目录运行，等待原程序及启动器退出，再按记录备份旧程序并替换；所有写入文件再次校验。新程序能正常读取工程库、素材和设置、打开界面并返回匹配版本的确认后，才提交更新。启动失败、取消或替换异常时恢复旧程序。

事务记录和原程序备份保存在本机。替换期间断电，下次双击稳定启动器会先恢复未提交事务，再打开原程序。已完成更新清理下载内容和暂存文件，下次手动检查会回收较早的成功备份，保留最近一次。

更新只处理程序清单里的文件，不触及 `data/`、个人短语、导入字体、共享设置或未知个人文件。路径须为合法相对路径，拒绝目录穿越、个人资料路径、Windows 设备名及目录链接。下载准备锁和安装文件锁防止同一目录并发更新；不同软件目录仍分别更新。

当前自动更新只接受兼容的工程数据库第 4 版、共享设置第 1 版。未来需要不兼容的数据迁移时，应另行设计迁移备份与回退，不能仅改版本号就绕过兼容性限制。

## 发布者操作

`npm run update:build` 在打包后生成三个更新附件，默认以 `releases/Memorybook-Windows-x64.zip` 作为上次版本基线，因此应先生成更新内容，再替换 releases 中的完整 ZIP。可用 `--base=` 指定其他基线。

签名私钥默认位于 `.local/update-signing-key.pem`，也可用 `MEMORY_UPDATE_SIGNING_KEY` 指定外部文件。**请单独备份私钥，不上传仓库或随软件分发。** 公钥位于 `assets/update-public-key.json`，打包进程序。已有用户后不要随意重建密钥，否则旧软件不能验证后续更新；更换密钥需要单独的信任迁移方案。该签名用于验证更新，无需购买 Windows 发布者证书。

正式发布前运行单元测试、原生更新/回退测试，以及真实 Electron 更新测试。后者构造隔离的下一版，验证关于页面不主动联网、手动检查、取消、差分下载、重启提交及个人工程保留。测试程序和测试更新源均不进入发布包。
