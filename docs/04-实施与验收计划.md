# 实施与验收计划

## 1. 交付阶段

按完整正式产品设计和编码，不采用 MVP 交付。P0–P4 是内部实施与验收顺序；P2 完成不能代替商业版本交付。商业发布要求全部约定范围、无激活使用、必要设置和质量门槛通过，明确列为后续或非目标的能力除外。

| 阶段 | 交付物 | 通过条件 |
| --- | --- | --- |
| P0 产品与设计定义（本轮） | PRD、交互与视觉规范、AI 数据协议、示例文档、验收计划 | 需求可追踪；假设与未决项有明确记录 |
| P1 交互原型 | 创建流程、编辑器、模板样页、AI 状态与导出检查原型 | 用户能在原型中理解照片裁切、批注自动保存与任务取消 |
| P2 编辑器闭环 | 上传、可编辑模板、封面、页面管理、保存恢复、PDF | 不依赖 AI 完成制作和导出，关键验收场景通过 |
| P3 AI 批注闭环 | 跨页批注、真实任务、全书锁、结果比对、取消与撤销 | 正常、失败、取消、断线与并发冲突均无数据损坏 |
| P4 商业发布验收 | 长册性能、兼容性、设置、自动发货、安装包（Windows 签名可选）、真实素材试用 | 正式范围完整；性能、数据可靠性、视觉、离线交付和订单链路全部通过 |

当前已实现桌面软件并生成 Windows 安装包。阶段表保留作为验收范围；实际已验证项目和仍需验证的外部平台、干净机器安装与订单链路，见 [开发运行与交付](07-开发运行与交付.md)。

## 3. 场景验收清单

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A01 | 导入 20 张照片、3 张透明贴纸和 1 张票根 | 透明通道保留，失败文件单独提示，用户可以改变照片顺序 |
| A02 | 生成封面并输入“明日世界”“北京” | 背景、标题、角标各为独立元素，任意一个可单独修改 |
| A03 | 上传已含文字的完整封面 | 默认不叠加额外标题，不将像素文字误标为可编辑文本 |
| A04 | 用横图填入竖框，移动和裁切 | 图片无拉伸，外框调整与框内裁切互不混淆，撤销恢复原状 |
| A05 | 修改长中文标题、字号和颜色 | 可正确换行；溢出有提示；PDF 字形与预览一致 |
| A06 | 复制、删除、重排内页 | ID 不冲突，素材引用有效，封面仍在首位，删除可撤销 |
| A07 | 三页五个元素写批注并刷新 | 已保存批注全部恢复，点击列表准确定位；未保存时有明显提示 |
| A08 | 替换带批注照片 | 原批注变为需复核，不能无提示提交给新图片 |
| A09 | 统一提交五条批注 | 等待时画布、键盘、批注、另一标签页及写接口均不能编辑 |
| A10 | AI 执行成功 | 所有有效操作一次提交，结果逐条可见，整批仅一个撤销步骤 |
| A11 | 一条要求不支持 | 该条保留内容和原因，其余可执行项统一应用，不声称全部完成 |
| A12 | 模型输出不存在 ID 或非法操作 | 整批验证失败，原稿和批注保留，不执行任意代码或文件操作 |
| A13 | 取消与完成同时发生 | 最终只出现取消或提交一种结果；取消后晚到回调无法写入 |
| A14 | AI 中刷新、断网、服务进程中断 | 重开恢复正确锁与任务状态；过期任务最终释放；不永久卡住 |
| A15 | AI 完成后又手动编辑并撤销 | 历史顺序正确，不跳过人工修改直接覆盖文档 |
| A16 | 导出含封面和封底的 18 页项目 | PDF 恰好 18 页、逐页对应、尺寸正确，不自动拼跨页或补页 |
| A17 | 导出中继续手动编辑 | PDF 保持开始时的版本，编辑器最新版本未丢失 |
| A18 | 缺失字体、素材失效、低清图片 | 前两项阻止错误输出；低清提供明确提示和继续选择 |
| A19 | 保存失败后继续操作与重试 | 明确未保存状态，重试成功前不宣称已保存、不启动 AI |
| A20 | 100 页长册与 500 素材引用 | 在固定测试设备记录内存、交互、保存和导出耗时，无崩溃或缺页 |

PDF 验收不只检查文件能打开：将导出各页渲染为图像，与相同版本设计预览比较，并人工检查中文、透明贴纸、图片裁切、旋转和页面边缘。PDF 字体应嵌入或使用经过一致性验证的渲染策略；优先保留可选择文字。

## 4. 样例与试用设计

准备三组经过许可的素材：演唱会（暗光、票根、长标题）、旅行（横竖混合、日期顺序）、日常手账（透明贴纸、长文字、重叠图层）。不要只用构图整齐的展示照片。

邀请 5–8 位目标用户做首轮可用性测试，观察是否能独立完成封面修改、照片裁切、三页批注与 PDF 导出。记录实际卡点，不能把样本规模当作统计验证。

## 6. 商业交付补充验收

以 [技术方案](05-技术方案.md) 和 [离线授权与自动发货](06-离线授权与自动发货.md) 为新增交付约束：干净机器断网安装与使用、应用无非 AI 主动联网、打开即用、固定内容自动发货、补发与技术服务范围、安装包（Windows 签名可选）及真实订单全链路测试。A09 的写接口指本机主进程接口；A13 的取消提交竞态在本机事务中裁决；A14 的应用进程重启使中断任务失效，不自动重发。

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A21 | 不同买家购买 | 固定发货内容包含完整软件包及说明；首次打开无需卡密 |
| A22 | 补发与首次启动 | 补发同一固定内容；全新目录直接打开；无激活或绑定 |
| A23 | 改设置后重开与软件升级 | 偏好正确恢复；默认尺寸不改变旧项目；配置迁移保留有效值 |
| A24 | 清缓存与重置设置 | 不删除项目、原图与历史；重置不移除 AI 凭证 |
| A25 | AI 中关闭 AI、设置写入失败、导出目录不可写 | 取消和设置状态一致，旧结果不回写；失败不显示成功，不偷偷改存其他目录 |
| A26 | 界面缩放与真实内容视觉检查 | 100%/125%/150% 下关键操作可达、文字清楚；高级选项折叠，状态与错误不只靠颜色 |
| A27 | 正式构建与故障注入评审 | 无 mock 成功路径、无效功能占位、空 catch 吞错、无限重试；磁盘满、坏工程、非法 AI 回包按明确错误路径处理 |

架构评审必须核对模块依赖方向、真实持久化、迁移、事务和安全边界；“商业级”不能仅靠命名或目录数量验收。发布前保留测试报告与已知限制，不以“后续重构补齐”为理由跳过阻断问题。

BYOK 验收：三协议请求与响应转换、Key 本机加密、变更 API 地址禁止自动复用 Key、仅主动调用联网、连接测试真实发起模型请求、不自动重试付费调用。取消后不承诺平台退费。Windows 证书缺失不阻止未签名包构建。
