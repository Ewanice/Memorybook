# 1.3.2 Sticker workflow fix

日期：2026-10-15。修复照片与贴纸选择器混用、全局贴纸没有出现在编辑器，以及 Codex 自由设计可以漏用已选贴纸的问题。软件生成路径继续为英文 ASCII。

## 使用流程

首页上传的贴纸进入全局贴纸库。新建纪念册时选中本次自动排版要用的贴纸，支持全选和清空；未选择时明确提示不会自动排入。选中表示本次可用素材池，固定排版按贴纸位置和页数轮用，不承诺每种贴纸都放一次。

生成后，“＋贴纸”显示全局贴纸和本册已有贴纸，即使新建时未选择也可以手动加入。“＋照片”只显示本册照片。替换贴纸时同样显示贴纸列表。贴纸导入按钮调用专用上传接口，同时写入全局库和本册素材；不会误走照片导入流程。

点击全局贴纸时，先将可信素材引用加入本册，再添加可编辑贴纸元素。主进程验证贴纸来源，保存遵守版本号和任务锁。全局贴纸移出后，已有工程和历史引用保持可用。

## 工程模型与兼容

Album 新增可选 assetLibrary: { photos: string[], stickers: string[] }，显式记录素材用途，未放进画布的贴纸也保留分类；同一张图可以同时用作照片和贴纸。分类与工程、备份、撤销和重做一同保存；引用必须对应工程内真实素材。

旧工程没有分类字段时，根据图片元素的 role 和本地贴纸库的素材编号识别；首次编辑或导入时保存分类。不根据扩展名或透明度猜用途，因此普通 PNG 照片不会自动被当成贴纸。

## Codex

固定排版原本已支持自动填充贴纸槽。现在协议进一步明确：有选择贴纸时，生成的内页必须实际使用至少一张已选贴纸。自由设计使用 sticker 元素和独立贴纸索引；固定设计选择具有贴纸槽的排版。

自由设计的最多 8 张预览，在有贴纸时分配给最多 6 张照片和 2 张贴纸。每张预览明确标注 kind 和各自数组的 index，避免照片和贴纸同为索引 0 时混淆。全部已选贴纸元数据仍随请求传递。

程序校验生成结果，若已选贴纸却没有任何贴纸元素，明确报错且不创建空有素材库的工程；不自动补一个随意摆放的元素，也不自动发起付费重试。已有工程可以直接通过“＋贴纸”补入，无需重新生成。
