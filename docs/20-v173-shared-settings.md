# 1.7.3：设置共享，工程独立

## 先区分两种行为

旧版本首次启动会把系统旧数据目录复制进软件目录，此后每份软件各自保存。这是一次性的复制，并非同步。因此 A 修改导出目录后，B 不会随之改变。1.7.2 取消了这次跨目录复制，但每个目录的设置仍然独立。

1.7.3 按新的产品要求，将设置和工程分开保存：同一 Windows 用户下运行的新版副本共用设置，工程和素材库继续各自独立。全部为本机操作，不需要账号、联网或服务器。1.7.2 及更早版本不会主动读取新的共享设置，需要升级。

## 保存范围

| 内容 | 位置与规则 |
| --- | --- |
| 导出目录、界面缩放、辅助线、默认尺寸与质量、外观 | `%APPDATA%/Memorybook/shared-settings/preferences.sqlite`，共用 |
| AI 平台、模型、加密 Key、Codex 连接与提示词 | 同一共享设置数据库；Key 继续由 Windows 本机加密，不发送到其他软件或上传到 GitHub |
| 自定义首页背景 | 共享设置目录的 `appearance/`，作为外观设置的附件保留；预览缓存位于各自 data 中 |
| 工程、照片、贴纸原图、工程历史、恢复副本 | 各自软件目录的 `data/`，不共享 |
| 贴纸库、排版库与排版草稿 | 各自工程数据库中，不共享 |
| 导入字体、个人短语 | 各自的 `materials/imported-fonts/`、根目录 `phrases.txt`，不共享 |
| 内置字体、纸张与程序 | 更新包提供的程序文件 |

设置 → 文件与导出可以查看实际路径。系统用户名及用户自行选择的目录可能包含中文，软件新建的目录名和分发文件名使用英文。

## 升级与多窗口

首次运行 1.7.3 时，如果当前 Windows 用户还没有共享设置，则以这份软件原有的本地设置作为初始值，没有旧设置时采用默认值。之后，其他副本的旧设置不会覆盖已有的共享值。建议先升级并打开设置正确的那份软件，再打开其他副本。

设置直接读写同一数据库，启动时读取最新值。已打开的窗口约每秒检查一次变化，仅刷新设置，不刷新或覆盖正在编辑的工程。保存通用设置时只合并本次实际修改的字段；同一字段已被其他窗口修改时拒绝旧值。AI 和 Codex 的未保存表单保留输入并提示重新读取，避免旧表单覆盖新配置。

数据库使用 WAL、写事务和等待锁来处理并发。AI 配置与加密凭证在同一事务内保存。共享设置另有一份一致性备份；发现物理损坏时保留原始数据库及 WAL/SHM，再尝试恢复备份。无效设置原文也保留，不把正常工程当成设置一起重置。

## 用户直接解压覆盖更新

1. 关闭正在使用的 Memorybook 窗口。
2. 将完整新包解压到旧版所在位置，覆盖程序文件。
3. 重新启动：工程、原图、导入字体和个人短语仍在原处，共享设置也不会被程序覆盖。

ZIP 不包含 `data/`、导入字体、根目录 `phrases.txt` 或共享设置数据库。默认短语存在程序的只读种子中，首次使用且根目录文件不存在时才创建。因此直接解压覆盖也不会覆盖个人短语。开发打包继续覆盖固定的 out/packages、out/delivery 和 ZIP 路径，保留目录里的个人资料。

**删除整个软件文件夹后，设置仍在；该文件夹内的工程不会自动保留。** 需要删除或换位置时，先备份工程或完整资料。此版本不把各个副本的工程合并成一个库，也不会把系统旧数据库的工程偷偷复制进新目录。

## 验证

80 项单元与持久化测试通过。正式 EXE 验证覆盖两个同时运行的副本、导出目录实时刷新、共享加密 Key 与首页背景、工程彼此独立、删除测试软件后新目录继承设置，以及程序覆盖更新后工程 ID、名称和个人短语保持不变。新目录验收使用隔离的共享设置目录，避免测试改动开发者真实设置。默认按 Windows 用户定位共享目录的规则另有测试。

仅供诊断或自动化测试的 `--settings-dir=` 可指定隔离设置目录。开发模式和显式 `--user-data-dir=` 的测试默认使用隔离设置，正式普通启动则使用上述 Windows 用户目录。测试参数不会写入分发包。
