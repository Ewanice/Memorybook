# 1.7.2：全新安装使用默认设置

> 1.7.3 起以 [设置共享与覆盖更新](20-v173-shared-settings.md) 为准：设置按 Windows 用户共享，工程和素材库仍按软件目录独立。以下旧版“每个新目录设置为空”的规则已被替代。

## 原因与修复

1.7.1 的分发 ZIP 没有包含用户数据库或本机设置，但首次启动逻辑会在软件目录没有数据库时，自动读取系统用户目录里的旧数据库，并复制旧工程、设置和凭证。因此，同一台电脑上解压到新的空文件夹，仍可能显示此前保存的导出目录。这属于启动迁移行为，不是把作者设置打进了软件包。

1.7.2 取消从系统用户目录或其他安装自动导入数据。全新解压目录首次启动使用默认设置：导出目录为空、AI 默认关闭、没有个人 Key、工程或个人素材库。旧系统目录完整保留，不删除、不改写。

在原软件目录升级时，已有 `data/` 正常保留；软件同目录的旧中文数据文件夹仍支持原地升级。迁往新目录时，由用户通过工程备份或完整资料备份主动导入。软件不会为了显示“默认状态”而清除既有工程和设置。

设置的“文件与导出”页新增“清除默认导出目录”，只清除该偏好，不动工程、素材或其他设置。之后再次导出时由用户选择保存位置，完成导出后仍会记住最后一次选择，属于正常偏好保存。

## 验证

此前的完整目录测试预先创建了空数据库，绕开了真实的首次启动迁移，本次移除这一步。新的正式 EXE 测试在无 data、无数据库、无指定 profile 参数的目录中启动，检查导出路径为空、工程库为空、AI 关闭且没有个人 Key/字体/贴纸/排版，并实际验证清除导出目录。

新增回归测试：旁边存在带旧工程、旧设置的其他安装时，新目录不读取该安装；新目录自行保存后重启保留自己的设置。原地升级测试继续检查旧资料源保留、原图复制及不覆盖现有数据库。

## 使用

要验证首次使用状态，请将 1.7.2 完整解压到全新的空文件夹。如果某个目录已经运行过旧版本，自动导入的数据已经保存在它的 data 中，更新不会自动删除；只需清除导出路径时，可用上述设置按钮。
